## 2. 一段视频如何变成场景

例如拍摄一个桌面摆件，手机围绕摆件移动：同一个角会出现在不同画面的位置。系统利用这些共同特征推算拍摄位置，再学习如何从不同角度呈现摆件。

| 阶段 | 做什么 | 本项目实现 |
| --- | --- | --- |
| 接收视频 | 检查工具路径、文件大小、扩展名和质量档位，创建任务 | Program.cs |
| 排队 | 同时只运行一个重建任务，避免多个训练任务竞争资源 | JobQueue.cs |
| 检查视频 | FFprobe 确认包含视频流，时长大于 0 且不超过 60 分钟 | Pipeline.cs：probe |
| 抽帧 | FFmpeg 把视频采样成图片，并限制图片尺寸 | Pipeline.cs：frames |
| 提取与匹配特征 | COLMAP 找到各张图中容易辨认的位置，再寻找跨图片的对应关系 | Pipeline.cs：features、matching |
| 稀疏重建 | 联合估算相机位置、朝向及部分三维点 | Pipeline.cs：reconstruction |
| 质量检查 | 选择注册图片最多的模型，检查是否有足够图片和三维点 | Pipeline.cs：validation |
| 去畸变 | 根据镜头参数校正图像，准备 Brush 输入 | Pipeline.cs：undistortion |
| 训练 | Brush 调整 Gaussian 场景，使渲染图片接近输入图片 | Pipeline.cs：training |
| 交付结果 | 检查最终导出文件和部分 Gaussian 属性，保存 scene.ply | Pipeline.cs、Program.cs |

当前 COLMAP 特征提取和匹配显式使用 CPU、4 个线程，匹配策略是图片全配对。没有加入 COLMAP 稠密重建或三角网格生成阶段。

快速档最多 80 帧、5,000 训练步；均衡档最多 160 帧、15,000 步。抽帧速率取每秒 5 帧与“档位帧数 / 视频秒数”中的较小值，所以并非视频越长，最终图片就越多。

## 3. 需要理解的概念

**相机位姿**是拍每张照片时相机在哪里、朝向哪里；它属于相机外参。**内参**描述焦距、成像中心等镜头成像信息，畸变参数描述镜头使直线弯曲等现象。**SfM** 是利用不同视角照片共同估计这些信息和三维结构的过程。COLMAP 的稀疏重建负责这一步。[COLMAP 教程](https://colmap.github.io/tutorial)

**注册图片**指成功求得相机位姿、纳入重建模型的图片。“注册率 80%”表示抽出的图片中至少八成参与了同一模型，不能理解成最终画面质量达到 80%。本项目还要求至少 10 张注册图片和 100 个三维点；重投影误差会显示，但当前没有对它设置拒绝阈值。

COLMAP 3.9.1 的主要模型文件：`cameras.bin` 保存相机模型与内参，`images.bin` 保存图像位姿及二维观测，`points3D.bin` 保存稀疏三维点及观测关联。它们是训练的几何基础，不是最终的 Gaussian 场景。[COLMAP 文件格式](https://colmap.github.io/format.html)

**Gaussian（高斯）**可以想成空间里一团边缘渐淡、可以拉伸和转向的半透明颜色。大量这样的元素叠在一起，从某个角度看就形成一张图像。相较只记录离散位置的普通点云，它还具有大小、方向、不透明度和随观察方向变化的颜色参数；球谐系数用于表达这种方向相关颜色。[3DGS 原论文](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/3d_gaussian_splatting_low.pdf)

**训练**是在当前场景上按已知相机视角生成图片，与原图比较，反复调整场景参数。这里训练的是这段素材对应的场景，不是训练一个通用大模型。增密是增加或拆分需要更多细节的 Gaussian；裁剪是移除贡献小等不需要的 Gaussian。训练完成后，查看器将 Gaussian 投影到屏幕并混合颜色，无需每次浏览都重新训练。[3DGS 项目](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)

**PLY** 是文件容器格式，不是“高斯模型”的同义词：普通点云也可以叫 PLY。当前查看器需要带 Gaussian 属性的 PLY，不能保证任意 PLY 都能正确显示。

Brush 0.3.0 接受带相机位姿的图片数据，支持 COLMAP 输入和命令行运行，使用 WebGPU 兼容技术和 Burn。不能因服务器有 NVIDIA 显卡就把本项目当成 PyTorch/CUDA 训练项目，也不能因宿主机能运行就认定容器内能运行。[Brush 0.3.0 官方说明](https://github.com/ArthurBrussee/brush/blob/v0.3.0/README.md)

## 4. 后端能力与边界

- Program.cs 提供健康、设置、任务列表、详情、日志、取消和 PLY 下载接口。浏览器通过轮询取得状态，当前没有 SSE 或 WebSocket 推送。
- JobQueue.cs 使用单消费者队列；关掉网页不会停止任务，但停止后端会中断计算，重启后不会断点续训。
- ProcessRunner.cs 以参数列表启动外部程序，收集标准输出和错误输出；取消和超时会尝试结束进程树。默认超时是每个工具进程 120 分钟，不是整个任务 120 分钟。
- JobStore.cs 使用每任务目录、job.json 和 run.log 保存状态与日志，没有数据库。保留输入视频、中间图片、重建数据和导出结果，当前没有自动清理或删除任务接口。
- ToolAvailability.cs 只判断工具文件是否存在。`toolsReady=true` 不证明二进制可执行、依赖完整、版本兼容或 GPU 可用；`/api/health` 也只证明 API 存活。
- Brush 进度依赖其输出被识别；没有进度输出不能推断为卡死。当前最终文件检查只验证文件大小、头部及部分属性，不是完整的渲染质量检查。
- 尚无账户、多用户隔离、断点续训、图片集上传、场景编辑或网格导出。当前适用范围是可信本地或内网环境。
